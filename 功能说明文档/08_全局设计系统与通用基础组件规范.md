## 一、 模块核心定位

全局设计系统是保障 Gemini UI Forge 界面美学、交互一致性与高维护性的基石。全项目彻底告别散落硬编码魔法数字（如 `8.dp`、`16.dp`、`440.dp`），建立了一套覆盖五阶弹窗宽度、强制封装组件注册表、视口智能碰撞感知与剪贴板异常自愈的标准组件库。

```
┌────────────────────────────────────────────────────────────────────────┐
│                        全局设计系统与 Tokens 规范骨架                   │
├────────────────────────────────────────────────────────────────────────┤
│ 1. 五阶弹窗宽度 Tokens (LocalAppSpacing)                                │
│    [440dp Alert] ─► [520dp Config] ─► [720dp Medium] ─► [960dp Large]  │
│    └─► [1280dp Huge 全景对比] (usePlatformDefaultWidth = false 逃逸)    │
├────────────────────────────────────────────────────────────────────────┤
│ 2. 强制封装组件注册表 (Mandatory Widget Registry)                      │
│    ├─ 统一下拉菜单: AppMenu (COMPACT 280dp / WIDE 320dp) + 黄金热区    │
│    ├─ 面板分割手柄: VerticalSplitter / HorizontalSplitter (零死区手势) │
│    ├─ 滚动条适配器: VerticalScrollbarAdapter (一键直达首尾胶囊)        │

│    ├─ 剪贴板动作链: Modifier.copyOnClick + rememberClipboardAction     │
│    ├─ 视口翻转提示: Modifier.tip (下边缘自动向上翻转防遮挡)             │
│    └─ 轻量气泡通知: Toast.show (单例分发，严禁手搓浮层)                │
├────────────────────────────────────────────────────────────────────────┤
│ 3. 架构红线: One Entity / One Composable Per File (单一实体单文件)      │
```

## 二、 核心功能与规范清单

### 1. 五阶标准弹窗宽度 Tokens 体系
全项目自定义弹窗（Dialog / Surface / AlertDialog）严禁手写非标数字，必须统一使用 `LocalAppSpacing.current` 声明的标准 Tokens：
1. **`dialogAlertWidth` (440.dp)**：专职于轻量警告、操作二次确认弹窗（如删除工程确认）；
2. **`dialogConfigWidth` (520.dp)**：专职于单列基础设置、简单表单配置（如新建视图、编译导出配置）；
3. **`dialogMediumWidth` (720.dp)**：专职于中型详情展示、图元重命名与普通列表弹窗；
4. **`dialogLargeWidth` (960.dp)**：专职于大型 PC 仪表盘、2 列 Bento、MCP 服务中心与调试控制台；
5. **`dialogHugeWidth` (1280.dp)**：专职于全景宽屏通信档案、切片导入微观校对（VerifyDialog）与全景对比编辑器；
- **平台默认宽度逃逸铁律**：所有自定义弹窗必须声明 `properties = DialogProperties(usePlatformDefaultWidth = false)`，防止 Compose 原生平台默认窄宽度（约 280~320dp）破坏设计排版。

### 2. 全局统一菜单组件体系 (AppMenu)
全项目严禁直接裸调 Compose 原生 `DropdownMenu`，必须统一复用 `AppMenu`、`AppMenuItemRow` 与 `AppMenuSectionHeader`：
- **二元分级尺寸契约 (AppMenuTier)**：
  - `AppMenuTier.COMPACT`：紧凑场景（单列枚举、协议切换、右键菜单），保底 280dp 宽度；
  - `AppMenuTier.WIDE`：复合宽屏选择器（模型选择、预设多分类），保底 320dp 宽度；
- **内置物理特性**：屏幕右边缘防甩飞位移修正、底部向上弹出负偏移补偿、视口高度 70% 滚动约束；
- **条目规范 (AppMenuItemRow)**：36dp 触控热区、图标 18dp、文字超长截断、选中对勾（Check）与悬停高亮。

### 3. 面板与视图分割线拖拽规范 (Splitter)
- 调宽手柄（`VerticalSplitter`）与调高握柄（`HorizontalSplitter`）统一基于 Compose 生产级 `Modifier.draggable` 封装；
- 显式设置 `startDragImmediately = true` 实现硬件级即时指针捕获；
- 拖拽回调采用 `rememberUpdatedState` 收拢，`onDragStopped` 100% 确保重置 `isDragging = false`，彻底根除高亮状态锁死缺陷。

### 4. 滚动条适配器与首尾直达胶囊 (ScrollbarAdapter)
- 纵向一律接入 `VerticalScrollbarAdapter`，横向接入 `HorizontalScrollbarAdapter`，严禁“裸奔”无滚动条的可滚动容器；
- 内置 `ScrollEdgeNavConfig` 一键开启“回到顶部 / 直达底部”双向微型操作胶囊，处于首尾时自适应隐藏，杜绝散落手写协程平滑滚动代码。

### 5. PC 交互按钮 Tooltip 视口智能翻转规范
- 桌面端所有交互按钮必须挂载 `Modifier.tip(...)` 悬浮提示；
- 宿主内置窗口视口边界碰撞算法：当交互组件位于屏幕底部边缘时，提示浮层**强制自动向上翻转显示**，严禁向下偏移遮挡按钮本体。

### 6. 单一实体与单一 Composable 单一物理文件红线 (One Entity Per File)
全项目严格贯彻极其严苛的代码可维护性标准：
1. **一个类一个文件**：凡 `class`、`data class`、`interface`、`enum class`、`object` 必须独立保存在与其同名的单一物理文件内，严禁在文件头尾就地顺手声明；
2. **一个 Composable 一个文件**：除极简的内联 Slot Lambda 外，严禁在同一个 `.kt` 文件中声明 2 个或以上独立命名的 `@Composable fun`；
3. **单文件规模黄金区间**：UI 文件代码量严格控制在 **100 ~ 300 行** 黄金区间（上限不超过 400 行）；业务中枢类（ViewModel/Manager）超过 500 行必须强制采用 Delegate（委托模式）剥离。

### 7. 真实物理鼠标自动化接管安全倒计时与置顶弹窗体系 (Real Mouse Automation Safe Overlay)
在涉及底层物理光标移动、操作系统真实点击拖拽、Win32/Robot/UIAutomation 等真实物理输入驱动调用的场景下，系统强制推行三阶段安全门禁：
1. **前置门禁（置顶提示 + 安全倒计时）**：物理接管前必须弹出系统级置顶（Always On Top）全屏遮罩弹窗，显示明确告警并触发 3 秒倒计时（`3... 2... 1...`），倒计时结束前严禁发送任何鼠标事件；
2. **执行锁定态**：倒计时结束后切换为“正在执行鼠标自动化操作...”，维持置顶保护物理光标运行轨迹，防止用户误触与争夺；
3. **后置自愈闭环（即时告知 + 3 秒自动平滑关闭）**：操作结束后立即切换为“✅ 鼠标自动化操作已完成！”，展示 3 秒后自动淡出并关闭弹窗，恢复用户正常交互。

### 8. 图标按钮与图标尺寸四阶守恒规范 (AppIconButton)
全项目所有图标按钮必须统一使用 `AppIconButton`，严禁在业务端直接裸写 Compose 原生 `IconButton` 或散落手写随意非标尺寸：
- **四阶成对守恒体系 (Four-Tier Paired Invariant)**：
  1. `AppIconButtonTier.MICRO`：容器 `20.dp`，图标 `12.dp`，圆角 `4.dp`（适用于树节点展开箭头、列表行内辅助标记、极紧凑操作）；
  2. `AppIconButtonTier.COMPACT`：容器 `28.dp`，图标 `16.dp`，圆角 `6.dp`（默认值，适用于侧边栏 Header、画布悬浮工具栏、代码块控制栏、紧凑搜索栏）；
  3. `AppIconButtonTier.STANDARD`：容器 `32.dp`，图标 `18.dp`，圆角 `6.dp`（适用于弹窗 Header 关闭键、主要面板顶部工具条、常规功能按钮）；
  4. `AppIconButtonTier.LARGE`：容器 `36.dp`，图标 `20.dp`，圆角 `8.dp`（适用于全局 TopBar 返回键、大厅全局操作、主工作区核心切换操作）；
- **尺寸接管与外部禁用覆盖**：按钮外框尺寸与内部图标尺寸 100% 由 `tier` 自动接管，业务层外部严禁显式添加 `.size()`、`.width()`、`.height()` 修饰符，彻底消除手写错误；
- **Tooltip 强制一等公民**：通过 `tooltip` 入参直接注入提示文案，底层自动挂载 `Modifier.tip(...)`，彻底根除漏加提示的体验缺陷；
- **内置四类视觉变体与加载态**：支持 `AppIconButtonVariant`（`GHOST` 幽灵、`FILLED_TONAL` 微底板、`OUTLINED` 描边、`FILLED` 实体强调），并原生支持 `isLoading` 平滑指示器与防重点击保护。

## 三、 跨模块联动关系

设计系统贯穿整个项目的全部工作台与数十个弹窗组件，所有界面自适应读取 `LocalAppSpacing`、`AppTheme` 并在主题与尺寸发生全局调整时，实现一处变更、全应用秒级自动响应：
- **弹窗尺寸 Tokens 联动**：
  - 440dp 轻量告警弹窗服务于 [01 工程大厅与项目管理体系](01_工程大厅与项目管理体系.md) 的工程删除与 [05 素材资产管理系统](05_素材资产管理与磁盘物理双向同步系统.md) 的切片物理删除二次确认；
  - 520dp 置顶安全弹窗服务于真实物理鼠标自动化接管门禁（3 秒倒计时前置拦截、执行中锁定提示与完成后 3 秒自闭环）；
  - 600dp Task 步骤列表弹窗服务于 [04 切片图集导入与透明图智能去背校对系统](04_切片图集导入与透明图智能去背校对系统.md) 的背景消除执行过程；
  - 720dp / 960dp / 1280dp 宽屏弹窗服务于 [07 游戏工程管线与转译导出系统](07_游戏工程管线与转译导出系统.md) 的工程创建向导与转译导出配置中心；
- **基础交互手柄联动**：
  - `VerticalSplitter` 与 `HorizontalSplitter` 全量承载 [02 Slots模板工作区](02_Slots模板工作区与图元编排系统.md)、[03 UI Studio独立工作台](03_UI_Studio独立工作台与切片排版系统.md) 与 [07 游戏专属工作台](07_游戏工程管线与转译导出系统.md) 的三栏拖拽排版；
- **统一下拉菜单与搜索栏联动**：
  - `AppMenu` 统一驱动 [06 AI多模态生成系统](06_AI多模态生成与智能体对话系统.md) 的模型下拉切换与 [05 素材资产管理系统](05_素材资产管理与磁盘物理双向同步系统.md) 的右键上下文菜单；
  - `AppSearchField` 统一接管素材库与图层树的关键字动态过滤；
- **单实体代码规范与编译中枢联动**：
  - 单一实体单文件与 100~300 行黄金区间规范，为 [09 三网协同调试与MCP服务中枢](09_三网协同调试与MCP服务中枢.md) 中 IntelliJ IDEA MCP 的单文件毫秒级局部增量编译提供了物理基础。

## 四、 行业业务规则与安全红线

1. **【严禁硬编码尺寸】**：代码评审中凡发现未经 Tokens 声明的裸 `dp` 常数（特殊 1px 细线除外），强制判定为不合格；
2. **【国际化 I18n 铁律】**：严禁在 UI 文件中硬编码中英文字符串，新增文案必须通过 `strings.xml` 注册并由 `stringResource` 注入；
3. **【平台默认宽度逃逸铁律】**：所有全屏或宽屏自定义弹窗必须声明 `DialogProperties(usePlatformDefaultWidth = false)`，严禁破坏 Tokens 设定的目标物理尺寸；
4. **【真实鼠标自动化接管安全门禁铁律】**：凡是在测试、校准或自动化中需要真实接管物理鼠标设备时，**必须强制先弹出置顶弹窗并倒计时结束后方可开始操作；操作结束后立即提示告知并在 3 秒后自动关闭**，严禁静默直接夺取光标控制权；
5. **【图标按钮强制封装与四阶守恒红线】**：全项目严禁裸调 Compose `IconButton` 散落手写随意尺寸，必须统一调用 `AppIconButton`，外框与内图标尺寸必须且仅能由 `tier` 成对守恒接管。
