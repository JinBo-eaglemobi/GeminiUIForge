## 一、 模块核心定位

在现代化游戏排版与工业级资产管线中，素材管理绝不能停留在轻量级内存字典。**素材资产管理系统**（UIAssetLibrary）为 UI Studio 提供了企业级的多级树形目录组织、基于内容密码学 Hash 的不可变资源唯一标识体系、与本地磁盘文件系统的实时物理双向映射，以及应对意外断电或外部改动的冷启动自愈扫描机制。

```

│                   素材资产管理中枢 (UIAssetLibrary) 拓扑                │
├────────────────────────────────────────────────────────────────────────┤
│ UI Studio 左侧素材面板 (AssetPanel)                                    │
│ ├─ 根目录 (Root)                                                      │
│ │  ├─ 📁 图标文件夹 (Icons)                                            │
│ │  │  ├─ 🖼️ back_btn.png   [Hash: 9a3f2c...] 80x84                     │

└────────────────────────────────────────────────────────────────────────┘
```

## 二、 核心功能清单

### 1. 素材资源唯一标识统归为 Hash 闭环体系
- **彻底废除易冲突的数字/随机 ID**：
  - 系统彻底废除了旧架构中不可靠的自增数字或随机字符串 ID 字段；
  - **全链路收敛为 Hash 唯一主键**：每一个素材切片（`UIAssetItem`）以其文件二进制内容的 SHA-256 Hash 值（如 `9a3f2c...`）作为唯一且不可变的主键；
  - **根本优势与强去重铁律 (Content Deduplication Invariants)**：
    1. **天然去重与复用**：导入或图集切片时，若遇到相同内容（相同 Hash）的图片，系统自动识别并复用已有资产项，清理冗余物理文件，并在界面提示复用跳过数量，绝不冗余占用存储空间；
    2. **切片批内去重防重名**：在图集切片批量入库阶段，自动对批内重复图形去重并复用首个切片资产，彻底杜绝单批次内生成多个同 Hash 素材条目；
    3. **素材库加载双通道自愈清洗**：素材库加载（`healAssetLibrary`）时，若检测到历史脏数据中存在相同 Hash 的重复资产项，自动执行清洗去重并立即刷盘持久化，保证内存与磁盘账本中每个 Hash 100% 唯一；
    4. **重命名免疫**：用户在界面任意修改切片显示名称（DisplayName）或将其移动到新文件夹，绑定的画布图元绝对不会丢失引用；
    5. **全链路统一驱动**：UIStudioState、UIStudioPreviewPanel、AssetLibraryDelegate 与 SliceImportDelegate 彻底统归由 `assetHash` 驱动。

### 2. 多级树形文件夹组织与交互 (Folder Hierarchy)
- **自由创建与层级归纳**：
  - 支持在素材库中无限层级新建、重命名与删除文件夹（`UIAssetFolder`）；
  - 支持拖拽切片在不同文件夹之间自由转移归类；
- **目录树人机工程学视觉规范 (Tree Hierarchy Visual Specification)**：
  - **文件夹状态前缀图标**：统一采用标准 `20.dp`（`Icons.Default.Folder` / `FolderOpen`，Primary 主色高亮），杜绝过小导致的单薄感与辨识度不足，并与叶子节点 `24.dp` 微缩图容器形成协调的视觉韵律；
  - **展开/折叠箭头指示**：采用标准 `18.dp`（`Icons.Default.KeyboardArrowDown` / `KeyboardArrowRight`），提供清晰的手势指引；
  - **图标文字间距**：文件夹图标与标题文字之间固定保留 `8.dp` 呼吸边距；
  - **行内快捷操作按钮**：目录行末尾更多操作菜单统一接入 `AppIconButton(tier = AppIconButtonTier.MICRO)`，消除散落硬编码尺寸；
- **快速检索与统计过滤**：
  - 内置素材搜索栏，支持按切片名称实时模糊匹配与高亮；
  - 每个文件夹动态显示其包含的切片数量徽章与占用空间摘要；
  - **本地点击防跳动锁机制**：用户在左侧素材树中直接点选素材切片时，系统通过 `skipNextScrollToSelected` 强制拦截视口自动滚动逻辑；仅当外部动作（如画布图元联动选择）且目标项在当前视口之外不可见时才平滑聚焦，彻底消除用户点击素材时列表强制将其滚到最顶部的严重视野跳跃缺陷；
  - **AI 对话上下文全层级透出与深度递归引用**：
    - 在项目级 AI 智能体对话输入框中键入 `@` 时，系统自动探测并枚举素材库中的全部树形文件夹（包括深度嵌套子目录）；
    - 文件夹候选项动态计算展示该目录及其全部子孙目录内的切片总数（`getItemsInFolderRecursive`）与层级展示路径（`getFolderDisplayPath`）；
    - 选中挂载后，大模型排版上下文自动获得该文件夹及其所有深度子目录的结构化精炼切片清单，严格以资产唯一 Hash 驱动（`- [hash: xxx] 文件名 [宽x高] | 角色: xxx`），彻底剔除冗余无用的磁盘物理路径；大模型在排版时统一使用 `assetHash` 唯一主键装配材质，支持一键点击弹窗预览完整 Markdown 素材表格（核心呈现资产唯一 Hash）。

### 3. 磁盘物理目录双向实时映射 (Physical Bi-directional Sync)
- **存储路径标准规范**：
  - 物理切片实际存储于：`~/.geminiuiforge/templates/{projectName}/assets/...`；
  - 树形结构与元数据存储于：`templates/{projectName}/asset_library.json`；
- **所见即物理存在**：
  - 在素材库中新建文件夹时，本地磁盘物理同步创建对应的真实文件目录；
  - 重命名或移动切片时，底层立即执行实际物理文件的重命名与跨目录移动；
  - 绝不在内存中搞“虚拟文件夹”，从根源上保障与外部 Git 协同或资源打包器的数据绝对一致。

### 4. 冷启动双通道自愈扫描引擎 (healAssetLibrary)
为防止用户在外部资源管理器中直接拷贝、重命名或误删文件导致的数据脱节，系统在工程加载与工作台初始化时强制运行双通道自愈：

```
                    UI Studio 工作台加载工程
                                │
               启动双通道自愈扫描 (healAssetLibrary)
                                │
        ┌───────────────────────┴───────────────────────┐
        ▼                                               ▼
【通道一：孤儿切片物理自动收录】                【通道二：死链切片自动剔除】
扫描 assets/ 物理磁盘所有图片                检查 asset_library.json 登记项
比对 JSON 记录，发现未登记文件                比对物理文件，发现磁盘已不存在
计算 SHA-256 Hash 并提取尺寸                 自动从素材树与索引中安全注销
自动补齐加入对应文件夹根节点                  防止画布呈现破图或调用崩溃
```

### 5. 破坏性操作二次确认即时物理落盘与级联删除 (executeConfirmedAction)
- **通用调度管道架构**：
  - 针对任何需要用户二次确认的破坏性或严肃变更操作，系统统一接入通用调度器 `executeConfirmedAction`；
  - **人机工程学心理契约**：二次确认一旦获批，立即执行【内存状态更新】与【后台物理磁盘 IO】，并在操作完成后**自动即时将账本持久化刷盘（如 `asset_library.json`）**，绝对杜绝等待用户在顶部导航栏手动寻找保存按钮才落盘的严重体验缺陷；
- **文件夹彻底级联物理删除 (Cascade Delete)**：
  - 用户在素材库删除文件夹时，弹出二次确认弹窗明确告知：“是否确认彻底删除文件夹「xxx」及其包含的全部素材切片？该操作将从磁盘永久物理删除，不可撤销”；
  - **确认后物理连根拔起**：
    1. 内存中级联移除目标文件夹及其所有子孙文件夹、以及归属于这些文件夹的全部素材条目；
    2. 物理磁盘上调用 `TemplateFile(folderRelPath).delete(recursive = true)` 彻底递归删除整个文件夹目录及内部所有图片切片；
    3. 立即将最新的 `asset_library.json` 原子刷盘落盘；
  - **彻底终结死而复生缺陷**：因磁盘目录与切片已物理不复存在，冷启动自愈扫描（`healAssetLibrary`）绝不会再次探测到残留目录并错误重建，彻底杜绝文件夹“删除后重新打开又复活”的严重退化；
- **切片物理删除二次确认**：
  - 点击删除素材切片时，弹出破坏性警示对话框（`AppConfirmDialog`）；
  - 经用户显式确认后，通过 `executeConfirmedAction` 同步抹除磁盘物理切片文件并即时更新落盘元数据记录。

### 6. AI 专属批量素材资源检索工具 (GetAssetsTool)
- **批量哈希定位能力 (Batch Asset Extraction)**：
  - 工具名称：`get_assets`
  - 核心入参：`assetHashes: Array<String>`（必填，素材唯一不可变 Hash 列表）；`includeImageData: Boolean = false`（可选，是否携带 Base64 图像数据）；`projectName: String?`（可选）
  - 核心产出：
    1. **全套规格参数**：文件名、物理宽高、推断语义角色（`inferAssetRole`）、所属文件夹与展示路径；
    2. **工程图元反查 (usedInBlocks)**：自动反查并统计当前工程各视图画布中哪些图元已引用了该素材；
    3. **多模态图像本体 (可选 Base64)**：当设置 `includeImageData = true` 时，自动读取物理图片并转码为标准 Data URL，让大模型能直接从视觉上审阅材质与排版契合度；
- **双通道一致性保障**：
  - `GetAssetsTool` 注册于 AI 核心暴露集（`ToolExposurePolicy.CORE_TOOL_NAMES`）；
  - 同时在通用素材管理工具 `ManageAssetLibraryTool` 中扩充 `action = "get_assets"`，实现 MCP 客户端与大模型对话双通道无缝调用。

### 7. UI Studio 切片资源工业级命名与智能识别规范 (Asset Naming & High-Confidence Recognition)
- **纯文件名独立词元解析 (Token-Based Parsing)**：
  - 彻底剥离素材相对路径（如 `templates/.../assets/...`），仅分析纯文件名（剥离后缀），杜绝系统父目录带来的单字母或关键字污染；
  - 采用标准分隔符（`_`、`-`、空格）切分独立词元，严禁跨词元任意匹配无边界字母；
- **工业级命名契约矩阵**：
  1. `SPIN_BUTTON` (核心旋转按键)：明确含 `spin` 且包含 `btn`/`button`/`main`/`auto`，且排除 `symbol`/`free_spin`；
  2. `BUTTON` (交互按键)：前缀 `btn_`/`button_` 或后缀 `_btn`/`_button`，或独立控制词元 `close`/`back`/`menu`/`play` 等；
  3. `BACKGROUND` (全景/局部底图)：前缀 `bg_`/`background_` 或后缀 `_bg`/`_background`；
  4. `HUD_FRAME` (边框/数值底栏)：前缀 `hud_`/`panel_`/`bar_`/`frame_` 或后缀 `_hud`/`_panel`/`_bar`/`_frame`；
  5. `TITLE_LOGO` (标题/Logo微标)：前缀 `logo_`/`title_`/`header_` 或后缀 `_logo`/`_title`；
  6. `REEL_SYMBOL` (游戏元素/滚轴符号)：带 `sym_`/`symbol_`/`card_` 前缀，或为标准扑克牌符号词元（如 `card_a`, `card_10`, `sym_k`）；
  7. `OVERLAY_FX` (光影/特效层)：前缀 `fx_`/`effect_`/`glow_`/`overlay_` 或后缀 `_fx`/`_glow`；
- **未识别切片角色彻底留白铁律 (Unrecognized Fallback)**：
  - 凡命名不规范（如 `D02`, `temp_1`, `123` 等）而无法达到 100% 高置信度推断的切片，**角色一律输出为 `null`（清单标注 `(角色未标识，由AI审阅图片)`，表格显示 `未标识 (待AI视觉审阅)`）**；
  - 坚决杜绝粗暴扣帽子或伪造兜底角色；在大模型系统指令（`spec_to_view.md`）中明确引导智能体：对于未标识角色的切片，必须调用 `get_assets(includeImageData = true)` 直接审阅其 Base64 画面视觉材质，自主决策其排版定位。

## 四、 行业业务规则与安全红线

1. **【绝对 Hash 主键红线】**：严禁在任何新业务逻辑中为素材重新引入易变 ID，必须 100% 遵守以 Hash 作为不可变单一事实源；
2. **【磁盘同步防悬挂】**：任何文件写入必须带有防并发瞬锁保护，物理移动失败时立即回滚内存状态，杜绝内存与磁盘脱节；
3. **【孤儿扫描零遗漏】**：外部手工拖拽拷入的图片，在下一次打开工作台时必须被 100% 自动扫描收录，杜绝资产丢失；
4. **【二次确认即时物理落盘铁律】**：全项目所有带有显式二次确认的破坏性或严肃变更操作，确认后必须通过 `executeConfirmedAction` 立即完成磁盘物理操作与元数据原子刷盘，严禁依赖手动保存，彻底杜绝冷启动状态回退；
5. **【高置信度角色识别与未识别留白铁律】**：严禁在素材角色推断中使用无边界单字母或包含系统路径进行正则模糊匹配；凡无法达到 100% 高置信度的非标命名切片，角色必须保持留白为 `null`，严禁强行分配伪造定位，由 AI 大模型结合多模态图像审阅自主决策排版位置。
