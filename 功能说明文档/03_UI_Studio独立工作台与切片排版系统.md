## 一、 模块核心定位

UI Studio 独立工作台是 Gemini UI Forge 针对现代游戏 UI 切片资产拼合与界面排版设立的专属工程环境。与传统 Slots 模板依赖整景设计图不同，UI Studio 采取**纯切片素材驱动架构**：支持多视图界面管理、树形素材库拖拽组装、容器专属独立视口多 Tab 编辑、自由拖拽分割线与毫秒级属性检查。

## 二、 核心功能清单

### 1. 三栏响应式架构与手势调宽系统 (Splitter System)
- **左右中三栏解耦与自由调整**：
  - 左侧复合面板、中间交互画布与右侧属性检查器通过 `VerticalSplitter` 相互解耦；
  - 基于 Compose 官方生产级 `Modifier.draggable` 一维手势封装，设置 `startDragImmediately = true` 确保指针即触即动、零启动死区；
  - 左右面板宽度支持双向自由拉伸，并具有合理的物理最小与最大边界夹具（如 240dp ~ 480dp），手势协程长效保活，彻底杜绝高亮锁死与手势中断。
- **左侧上下子面板与水平手柄 (HorizontalSplitter)**：
  - 左侧上栏为页面视图列表（ViewsPanel），下栏为树形素材库（AssetPanel）；
  - 中间镶嵌 `HorizontalSplitter` 水平分割手柄，支持上下自由调整列表与素材库的显示高度配比。

### 2. 页面视图管理系统 (ViewsPanel)
- **多页面/多场景统一管理**：
  - 支持在一个工程中创建并管理多个独立的游戏视图（如 Main 主界面、Lobby 大厅、Settings 设置弹窗、Backpack 背包等）；
  - 支持视图新建、重命名、复制副本与物理删除（含二次确认保护）；
  - 单击视图项快速在中间画布加载其图元树，双击可在顶部标签栏开启独立视口。

### 3. 多标签独立视口与组件-页面一体化系统 (Viewport Tabs & Component-Page Unification)
- **复合组件与视图页面 (UIStudioPage) 1:1 单实例强绑定**：
  - UI Studio 彻底废除传统易割裂的独立 `CONTAINER` 类型概念，实行“组件即页面”的一体化架构；
  - 凡是由多切片组合而成、或包含内部子图元的复合组件（例如老虎机滚轴 `slots_window`、控制底栏 `bottom_control_hud`），系统均自动在工程中为其生成并绑定对应的独立子页面（`UIStudioPage`），具有独立的视口分辨率、背景色与子图元列表；
  - 左侧「视图界面」面板采用层次化树状渲染，根页面下方紧随并缩进展示其所绑定的子页面（带有 `↳` 箭头与专属「组件」徽章）；
- **组件页面视口新开与聚焦**：
  - 双击画布中的复合组件、或在左侧「视图界面」单击子页面条目，系统自动以一等公民 Page 形式在顶部标签栏新开以该组件命名的专属标签页（`openViewTab`）；
  - 画布视口自动 Fit 聚焦到该组件子页面，中间画布渲染并接收该组件直接子图元的手势选中、拖拽与拉伸，彻底杜绝多层嵌套选不中的痛点；
- **父子页面双向联动与独立性守恒**：
  - **主界面调整不影响子组件**：在主页面（如 MainPage）调整该复合组件整体的 X/Y 或宽高时，仅改变其在主页面的承载形态，子组件内部的相对坐标与排版保持独立守恒；
  - **子界面修改实时镜像回显**：在组件子页面内部选中子图元修改 X、Y、宽 W、高 H 时，不仅当前子页面画布与微缩预览图即时变化，主页面中的对应复合组件也会实时镜像更新；
  - **图片渲染绝对贴合边界**：画布组件与微缩预览均采用 `ContentScale.FillBounds` 渲染，使图片严格按照用户设定的 `宽 W × 高 H` 矩形外框等比或拉伸贴合，杜绝单边修改宽高图片不变化的现象；
- **标签页状态管理与职能单一化**：
  - 顶部标签栏统一管理所有根页面与组件子页面 Tab，支持多标签平滑切换、关闭全部标签页（`AppIconButton` COMPACT 阶）；新建视图入口统一且唯一收拢于左侧「视图界面」面板 Header，确保顶栏功能纯粹。

### 4. 素材切片拖拽排版与画布交互
- **切片拖拽即生成图元**：
  - 支持从左侧素材库中选中任意切片，直接拖拽至中间画布释放；
  - 系统自动根据切片真实物理分辨率初始化图元尺寸，并自动挂载对应切片资产 Hash；
- **微观对齐与智能吸附**：
  - 画布内置边缘几何对齐辅助线，图元在移动或拉伸时，靠近相邻图元或容器边缘（$\le 5\text{px}$）自动触发磁力吸附；
  - 8 方向拉伸控制锚点 100% 统一复用 `RectTransformHelper`，光标物理绝对定位。

### 5. 右侧动态属性检查器 (PropertyPanel)
- **切片排版专属极简属性**：
  - 专职于图元几何变换（X、Y、Width、Height）、不透明度（Opacity）、图元类型（Button、Image、Text 等；UI Studio 彻底排除传统 CONTAINER 冗余类型，多元素组合统一通过独立页面绑定实现）；
  - **豁免生图组件**：因 UI Studio 属于纯切片排版，属性面板彻底去除冗余的 AI 生图提示词模块，保持面板紧凑纯净；
  - 数值调节一律接入 `NumberOutlinedTextField`，指针悬停即可滚轮平滑微调。

### 6. 悬浮式 AI 架构师协同入口
- 画布右下角常驻悬浮轻量级 AI 对话胶囊，一键唤起 `UIProjectAiStudioDialog` 项目级 AI 架构师；
- 架构师具备完整感知当前视口图元树、素材库清单与排版状态的能力，支持自然语言分发排版指令。

```

│                           │      打开 AI 协同    ├─────────────────────────────┤
│                           ├────────────────────►│ UIProjectAiStudioDialog     │
│                           │      转译代码导出    ├─────────────────────────────┤

└───────────────────────────┘                     └─────────────────────────────┘
```

1. **与切片导入校对弹窗联动**：外部导入 SpriteSheet 图集后，自动进入[04 切片图集导入与透明图智能去背校对系统](04_切片图集导入与透明图智能去背校对系统.md)的校对界面，完成去背与吸附后批量入库并展现在 AssetPanel；
2. **与磁盘物理文件实时双向同步**：任何素材文件的重命名、文件夹归类或删除，秒级同步更新磁盘物理文件与 JSON 元数据，详见[05 素材资产管理与磁盘物理双向同步系统](05_素材资产管理与磁盘物理双向同步系统.md)；
3. **与项目级 AI 对话中枢联动**：常驻悬浮入口一键唤起架构师，详见[06 AI多模态生成与智能体对话系统](06_AI多模态生成与智能体对话系统.md)，生成的切片排版方案在气泡中以常驻操作胶囊呈现，仅在用户主动点击「应用排版方案到画布」时才弹出确认弹窗，彻底杜绝会话结束或生图完毕时的突兀强弹窗打断；
4. **与游戏工程转译管线联动**：完成界面切片排版后，通过[07 游戏工程管线与转译导出系统](07_游戏工程管线与转译导出系统.md)一键导出为 FGUI 布局与 HTML 预览。

## 四、 行业业务规则与安全红线

1. **【素材唯一主键 Hash 守恒】**：素材切片在整个工作台内以内容 SHA-256 Hash 为唯一不可变标识，杜绝同名重命名引发的资产错乱；
2. **【分割线手势保活铁律】**：严禁在业务界面裸调手势，必须统一复用[08 全局设计系统与通用基础组件规范](08_全局设计系统与通用基础组件规范.md)中的标准 Splitter 组件，确保拖拽停止时 100% 释放拖拽状态；
3. **【视口状态无损切换】**：多标签页切换或退出进入容器视口时，原视口的缩放比例与平移偏移行程必须无损保留；
4. **【排版应用显式授权触发红线】**：AI 生成的排版方案严禁在对话流式结束或生图工具收口时自动向画布中央强推全屏模态弹窗，必须严格遵循“气泡常驻操作胶囊 + 用户主动点击按需唤起确认”的无感原则，保障用户视觉审阅与排版探索的绝对掌控权；
5. **【全平级页面与多重引用实例架构红线】**：UI Studio 内部所有页面（`UIStudioPage`）地位完全平级，无任何硬编码的“谁是谁的子页面”层级从属。页面间通过组件实例的 `targetPageId` 进行单向或多重随意引用；源页面修改时自动跨页面将内部元素镜像同步到所有引用实例中，而在宿主页面调整实例坐标与宽高仅影响其实例外观，确保任意组件可在全项目多页面中自由复用；
6. **【原图尺寸物理守恒与一键复位红线】**：属性面板必须提供「原图尺寸」一键复位能力，自动依据图元绑定的素材物理 Hash（或引用页面的源尺寸）秒级复位当前组件的宽 W 与高 H（保持左上角定位恒定），杜绝拉伸失真后无法还原初始比例的体验缺陷；
7. **【项目公用配置文件与复合页面分包存储红线】**：UI Studio 项目工程存储严格遵循项目公用配置与复合页面分包架构（对齐 Figma / VSCode 工业级工程标准）。主配置文件 `template.json` 彻底纯净化为项目级公用配置文件（`UIStudioProjectConfig`，`formatVersion: "2.0"`），专职记录工程元信息（`projectId`、`projectName`、默认基准分辨率 `defaultCanvasWidth/Height`、活跃视图 `activeViewId`）以及 `pageIndex` 相对文件索引清单，绝对禁止包含任何界面专属私有信息；各个平级视图界面的独立宽高、背景色及完整图元树 100% 独立保存为 `templates/{projectName}/pages/{pageId}.json` 单文件；所有 JSON 文件的物理落盘必须通过 `saveToFileAtomic` 执行原子交换协议（Temporary Swap + 底层 `fsync` 硬件刷盘 + `ATOMIC_MOVE` 原子替换），彻底杜绝系统崩溃或断电导致配置坏损；系统加载时自适应优先解析新版公用配置并按索引组装，同时向后兼容存量老工程并执行无感自愈拆分。
