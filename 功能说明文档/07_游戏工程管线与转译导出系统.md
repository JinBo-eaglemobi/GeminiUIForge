## 一、 模块核心定位

游戏工程管线与转译导出系统是 Gemini UI Forge 直面真实游戏生产环境的交付中枢与运行测试沙盒。它将设计排版好的图元拓扑、切片素材与样式配置，直接落地到真实的游戏工程骨架中（如 LayaAir、FairyGUI、Cocos 等），并提供集成的端到端测试工作台，支持直接在软件内进行 Web 游戏热预览与实时日志调试。

```
┌────────────────────────────────────────────────────────────────────────┐
│                        游戏工程管线与转译导出体系                        │
├────────────────────────────────────────────────────────────────────────┤
│ 1. 游戏工程创建与环境向导 (GAME_PROJECT_MANAGER)                        │
│    ├─ 左侧双模式向导: [从 Git 仓库克隆] vs [独立新建 UI 项目 (UI Studio)] │
│    └─ 右侧环境检测面板: 3 大类 7 项工具链环境就绪度实时扫描 (Node/Git/JDK)│
├────────────────────────────────────────────────────────────────────────┤
│ 2. 游戏项目专属工作台 (GAME_PROJECT_WORKSPACE)                          │
│    ├─ 顶栏元数据: 项目名称 / 游戏代号 / 语言 / 包管理器 / 物理路径直达 │
```

## 二、 核心功能清单

### 1. 游戏工程创建向导 (GameProjectCreateScreen)

在大厅点击 `+ 新建游戏项目` 虚线卡片即可呼出本向导。界面采用左右分栏排版：

#### 左侧：工程创建双模式分段器
- **模式 A：从 Git 仓库克隆**：
  - **项目基本信息**：
    - 项目名称（如 `GameMania`）；
    - 仓库地址（支持 HTTPS 与 SSH 协议，如 `git@github.com:...`）；
  - **凭据管理与连通性自测**：
    - 支持配置 SSH 密钥或 Personal Access Token 令牌凭据；
    - 配备 `测试连接` 按钮，直接探测远程仓库可达性，测试成功显示绿色对勾反馈；
  - **高级选项配置**：
    - 保存路径：指定克隆落盘的本地工作目录（附带系统文件夹选择手柄）；
    - 核心开发语言：下拉选择 `TypeScript`（默认）或 `JavaScript`；
    - 包管理器模式：单选配置 `pnpm`（推荐，高速硬链接）或 `npm`；
  - **执行操作**：底部大胶囊按钮 `克隆并创建工程`，自动在后台拉取仓库、校验依赖并注册至工程大厅。
- **模式 B：独立新建 UI 项目 (UI Studio)**：
  - **项目名称与目录**：输入工程唯一名称（如 `New_UI_Project`）与本地磁盘保存路径；
  - **5 大预设画布分辨率卡片**：
    1. `1920 × 1080`：标准 16:9 横屏 FHD（主流 PC / 平板 / 横屏 Slots 游戏）；
    2. `1280 × 720`：经典 16:9 横屏 HD（轻量级休闲网页游戏）；
    3. `1080 × 1920`：标准 9:16 竖屏 FHD（现代移动端竖版 Slots 游戏）；
    4. `720 × 1280`：经典 9:16 竖屏小屏（移动端小游戏）；
    5. `自定义分辨率`：允许自由输入宽度与高度数值；
  - **执行创建**：一键生成独立 UI Studio 工程骨架，直接跳转进入 [03 UI Studio独立工作台与切片排版系统](03_UI_Studio独立工作台与切片排版系统.md)。

#### 右侧：开发环境与工具链就绪度检测面板 (7/7 Ready)
在创建游戏项目前，系统自动在后台执行 7 项核心开发工具链的活体扫描，并在右侧卡片中以状态列表直观展示：
1. **Web 运行时与包管理器**：
   - `Node.js 运行时`：检测版本号（如 `v24.19.0`），标明执行路径；
   - `npm 包管理器`：检测版本号（如 `v11.17.0`），标明全局镜像源与路径；
   - `pnpm 高性能包管理器`：检测版本号（如 `v10.34.1`），确认硬链接缓存就绪；
2. **版本协作与辅助脚本**：
   - `Git 版本控制`：检测版本号（如 `v2.53.0`），确认终端环境变量可用；
   - `Python 脚本解释器`：检测版本号（如 `Python 3.11.9`），用于离线抠图与图元分析；
   - `pip 包管理工具`：检测版本号（如 `pip 25.0.1`）；
3. **宿主 JVM 构建环境**：
   - `Java JDK 环境`：检测锁定 JDK 25.0.2 版本，确保 KMP 共享层与桌面宿主顺畅编译；
- **自愈与刷新**：顶部配备 `刷新` 手柄，缺失组件时给出官方安装指引，全绿（7/7 就绪）时放行全部高级编译动作。

### 2. 游戏项目专属工作台 (GameProjectWorkspaceScreen)

在大厅点击带有 `🎮 游戏项目` 标签的卡片（如 `GameMania`），直接进入专属游戏工作台。整体布局分为五大交互区域：

#### ① 顶部项目状态栏
- **项目身份摘要**：展示项目名称、游戏内部标识、开发语言（TypeScript）、包管理模式（PNPM）；
- **物理路径直达**：展示工程在本地磁盘上的绝对路径，右侧配备 `打开目录 (文件夹图标)` 按钮，一键调起 Windows 资源管理器定位。

#### ② 左侧项目资源代码树 (Project File Tree)
- 以层次化目录树直观展开游戏工程的物理结构：
  - `build/`：编译构建输出目录；
  - `common/`：游戏通用基础类库与事件总线；
  - `game/`：核心玩法业务逻辑与状态机；
  - `res/`：游戏 UI 切片图集、音频、Spine 动画等静态资源；
  - 核心配置文件：`package.json`、`tsconfig.json`、`GameConfig.json` 等；
- 支持展开/折叠文件夹，单双击文件可快速查看或在编辑器中打开。

#### ③ 中间嵌入式 Web 热预览与测试视口
- **多页面视图切换器**：
  - 顶部标签栏支持在 `index.html`（主游戏视口）、`index2.html`（测试/辅助视图）等多个入口间无缝切换；
- **运行模式双切**：
  - `Demo 模式`：运行纯净发布态页面，验证真实玩家视角下的渲染效果；
  - `Debug 模式`：开启性能监控面板（FPS、DrawCall、内存）与调试网格；
- **视口控制工具栏**：
  - `刷新 (↻)`：强制重新加载页面，拉取最新编译的 JS 代码与 UI 布局；
  - `全屏 (⛶)`：将 Web 游戏视口最大化铺满工作区；
  - `地址栏展示`：直观展示当前视口所加载的本地服务地址（如 `http://127.0.0.1:60227/bin/index.html`）。

#### ④ 底部嵌入式实时控制台 (Console Panel)
- **多级别日志分流过滤**：
  - 顶部提供 `ALL`、`INFO`、`WARN`、`ERROR` 四态分段过滤器与条目计数徽章；
- **游戏引擎控制台消息捕获**：
  - 完整捕获底层浏览器与游戏引擎标准输出（如 LayaAir 的 `[Audio] AudioContext init`、`[tsCore] game loop started`、WebGL 渲染警告等）；
  - 每条日志带毫秒级时间戳、日志级别颜色标识（黄色的 WARN、红色的 ERROR）；
- **操作手柄**：右侧配备 `清空日志 (扫把图标)`，支持一键清空堆栈。

#### ⑤ 右侧页面与调试信息抽屉
- 可折叠收起，展示当前加载视图的运行参数、视口缩放比例以及跨平台转译导出配置。

### 3. 统一编译器服务与导出配置 (CompilerService & CompileConfigDialog)

负责将工作区中的图元树、属性配置与素材，自动化转译导出为游戏框架标准资产：
- **三级可配置导出参数**：
  1. **运行环境根目录 (`rootDir`)**：指定游戏主工程的物理根路径；
  2. **资源保存目录 (`outputDir`)**：指定编译后 UI 配置文件与伴生切片的输出目录；
  3. **资源混淆与安全保护 (`obfuscateAssets`)**：支持生产级资产 Hash 混淆与路径打散，防止敏感商业素材被外部轻易爬取；
- **持久化配置中心兜底**：
  - 编译配置持久化保存在用户工作区配置中，下次打开自动回填，无需重复配置；
- **空路径阻断拦截**：未指定 `rootDir` 或 `outputDir` 时，系统在弹窗层严格阻断并弹出 Toast 警示，杜绝将文件写到非法未定义路径。

---

### 4. 实时图层蒙版 1:1 比对预览 (OverlayPreviewDialog)

- **1:1 几何绝对校对**：
  - 在导出前或排版后，随时一键唤起全景蒙版预览弹窗；
  - 将原始设计参考图以半透明方式覆盖在当前编译排版图层之上；
  - 支持滑动条无级调节蒙版不透明度（0% ~ 100%），快速暴露出文字偏移、按键错位、底座截断等微观缺陷。

## 四、 业务规则与安全红线

1. **【宿主内置服务优先铁律】**：HTML 测试与 Web 视口必须复用宿主轻量服务，禁止在后台自起未纳管的第三方 HTTP 服务进程；
2. **【单一终端编译校验红线】**：凡涉及命令行编译验证，一律且仅指定单一终端模块编译任务（如 `:desktopApp:compileKotlin`），严禁并列上游 `:shared` 任务；
3. **【空路径阻断拦截】**：未指定 `rootDir` 或 `outputDir` 时，系统在弹窗层严格阻断并弹出 Toast 警示，杜绝将文件写到非法未定义路径；
4. **【真实鼠标自动化安全红线】**：凡在测试游戏工作台手势、Web 视口交互时涉及到真实接管物理鼠标设备（如 OS 真实光标移动、Win32 消息级点击）的操作，**必须先弹起置顶弹窗并触发 3 秒安全倒计时**，结束后方可执行；并在测试完毕后即时告知且在 3 秒后平滑自动关闭弹窗，坚决杜绝静默夺取物理鼠标控制权破坏用户工作流。
