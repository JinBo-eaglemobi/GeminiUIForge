## 一、 模块核心定位

AI 体系是 Gemini UI Forge 的智能大脑与核心生产力引擎。系统覆盖了从**微观图元 AI 生图替换**、**全图多模态模板反向生成**，到**项目级 AI 架构师对话协同**（图元布局理解、代码建议、资产检索）。系统底层遵循企业级四层协议解耦标准，在保证极致大模型隐式缓存命中率（降低延迟与 Token 开销）的同时，提供完整的离线报文审计与图片缓存自愈机制。

## 二、 核心功能清单

### 1. 标准双语提示词编辑器 (BilingualPromptEditor)
- **中英双语无缝切换与智能参考**：
  - 单行分段按钮（SegmentedButton）结构，防换行折叠；
  - 支持分别独立编辑中文提示词（`userPromptZh`）与英文专业提示词（`userPromptEn`）；
  - 跨语言智能占位：编辑中文时自动浮现英文参考文本，反之亦然；
- **胶囊式 AI 提示词智能优化**：
  - 内置 34dp 优化按键，一键调取大模型对原始粗糙描述进行艺术风格、光影材质与细节扩充；
  - 自带平滑加载动画与多重点击防抖拦截；
- **变动感知与显式确认同步**：
  - 具备脏数据感知机制，用户修改或 AI 优化后动态高亮“确认修改”；
  - 只有显式点击确认后方才持久化回图元模型，杜绝非预期篡改。

### 2. 批量资产生成中心 (BatchAssetGenDialog)
- **纯容器智能过滤**：
  - 自动遍历当前工程图元树，100% 自动剔除所有纯容器（`isPureContainer = true`）与空白背景；
- **队列调度与进度回显**：
  - 支持全选、反选、单图元勾选；
  - 顺序/并发分发生图请求，实时展示生成缩略图与单项耗时，生成完毕后支持一键全量替换至工作区。

### 3. 项目级 AI 架构师通用对话体系 (CommonChatStudioDialog)
- **业务解耦与通用插槽模型**：
  - 全项目对话体系收拢于纯净通用组件库（`component/chat`），严禁业务专有逻辑污染；
  - 开放四重插槽扩展定制：顶部操作栏动作（`topBarActions`）、单消息气泡动作（`messageActions`）、输入框前置工具（`inputLeadingActions`）与后置发送扩展（`inputTrailingActions`）；
- **@提及图元与切片联想系统 (Mention System)**：
  - 用户在输入框键入 `@` 时，实时呼出历史引用、切片素材、素材库文件夹、视图界面与图层图元联想悬浮卡片（`MentionItemRow`）；
  - **素材库文件夹（含深度子文件夹）定向注入**：
    - 支持实时探测素材库中的全部自定义文件夹，展示包含切片总数（含全部子孙目录统计）及完整层级相对路径；
    - 选中文件夹后，挂载为 `📁 文件夹名 (共 N 项)` 专属药丸，与“全部素材库清单”同等待遇；
    - 发送时自动深度递归提取该文件夹及其所有深度子目录内的全部素材，按 `AssetManifestHelper` 转换为紧凑清单 `<asset_folder_manifest>`，**严格遵循资产唯一 Hash 驱动契约**（格式为 `- [hash: xxx] 文件名 [宽x高] | 角色: xxx`），彻底剔除无意义的本地物理文件路径；大模型在调用万能排版工具（`edit_view_layout`）装配图元时，一律使用该 `assetHash` 唯一主键精准绑定材质；
    - 会话气泡中的药丸与输入框胶囊均支持点击弹出 Markdown 沉浸式切片清单表格预览，表格核心字段由切片名、资产唯一 Hash、尺寸及语义角色构成，零冗余路径字段；
  - 采用跨平台纯 Kotlin 集合与模糊拼音/字母匹配，高亮命中字符；
  - 点击选中的图元/切片作为上下文结构化卡片挂载在输入框，发送时自动携带该图元的精确几何参数与切片信息；
- **剪贴板位图快捷捕获**：
  - 输入框原生监听系统级快捷键 `Ctrl+V` / `Cmd+V`，直接读取系统剪贴板中的截图或位图，秒级挂载为对话附件；
- **大模型动态探测与思考等级**：
  - 动态从 `GeminiModel.entries` / `StudioModelResolver` 读取最新可用模型矩阵，绝不硬编码老旧版本；
  - 集成思考等级调节器，按需调节思考深度（Low、Medium、High）。

### 4. 四层协议载荷解耦架构规范 (Four-Tier Payload Decoupling)
系统与大语言模型通信严格遵循工业级四层物理载荷解耦：
1. **纯净静态系统指令 (Pure Static System Instruction)**：
   - `systemInstruction` 专职且仅承载智能体元身份定位与安全准则；
   - **严禁拼接动态图元树或临时文档**，确保系统指令全局静态一致，100% 触发大模型官方隐式上下文缓存（Implicit Caching），极速降低延迟；
2. **外部资料的数据属性隔离**：
   - 用户拖入的参考文档、需求表仅作为用户消息内的 `<reference_documents>` 隔离数据块传输，并附带防注入隔离声明；
3. **动态环境轮次注入 (Workspace Observation)**：
   - 当前画布视口分辨率与素材状态作为运行时环境观察，绑定于提问时刻的当前轮次，杜绝跨轮次幽灵状态污染；
4. **原生 Function Calling 工具调用**：
   - 技能与操作通过标准工具定义下发，拒绝长篇大论的手册塞入人设；
   - 默认下发精炼核心工具（`CORE_TOOL_NAMES`），并专属配备素材资产清单查询工具 **`list_assets`** 与批量素材详情提取工具 **`get_assets`**，支持大模型在规划布局或发现引用失效时，全景获取库内切片清单与 Hash，并通过 `assetHashes: Array<String>` 批量提取素材真实规格、语义角色与可选的 Base64 图像，彻底打通“清单检索 -> Hash定位 -> 排版装配”的完整闭环链路；
   - **跨通道人机问询与交互工具常驻暴露**：问询与通知工具（`ask_user_question`、`ask_user_choice`、`ask_user_confirmation`、`notify_user`）统一定位于 `service.tool.shared` 共享包并在 `AiToolRegistry` 注册；其中核心问询工具 **`ask_user_question`** 与即时通知 **`notify_user`** 纳入 `ToolExposurePolicy.CORE_TOOL_NAMES` 常驻下发给大模型，确保大模型在提呈界面方案、收集修改意见或执行重大操作前，主动分发结构化单选/多选卡片弹窗，杜绝退化为纯文本问答。

### 5. 通信报文审计与本地缓存自愈机制
- **标准化磁盘分级存储**：
  - 生成图片落盘：`~/.geminiuiforge/templates/{projectName}/assets/{blockId}/`；
  - 原始通信完整报文：`~/.geminiuiforge/sessions/{safeScope}/{sessionId}/traffic/`；
- **报文检视与巨型载荷脱敏折叠**：
  - 通信报文档案卡片针对请求/响应报文中数万至百万字符的巨型 Base64 图片载荷与 Gemini 3 系列思维链签名（`signature` / `thought_signature`）自动执行 UI 级脱敏折叠，彻底根除 Compose 文本组件内存溢出与主线程掉帧；
  - **双模态操作与二元差异化查看器**：卡片 Header 动态识别并展示“含图像”（`Image`）与“含签名”（`Psychology`）双徽章，在卡片操作栏与报文文本底部提供直达按钮；图片载荷唤起带格式魔数校验（PNG/JPEG/WEBP/GIF）的高清 Base64 图像预览器，签名载荷唤起思维签名查看器并支持一键复制，实现图像与数字签名的二元完全解耦；
- **自动再次缓存与自愈恢复**：
  - 当本地磁盘的生成图片被意外删除或转移时，用户在历史会话中点击「应用」，系统自动回溯读取对应轮次的 `RESP.json` 完整通信报文，重新解码提取 Base64 图片数据并无感重新写回磁盘，实现绝对的高可用闭环。

### 6. Interactions API 云端全生命周期管控与过期自愈重锚定机制
- **云端状态物理销毁闭环 (DELETE /v1beta/interactions/{id})**：
  - **单轮撤销回退**：当用户删除单条模型消息（`deleteChatMessage`）时，系统自动提取该轮次绑定的 `interactionId`，在后台异步分发调用 Google 官方 DELETE 接口注销云端节点；同时自动将会话的 `latestInteractionId` 精确回退至剩余有效历史消息中的最后一条节点 ID 并原子持久化；
  - **全会话物理注销**：当用户清空当前会话（`clearCurrentChatSessionMessages`）或删除完整会话（`deleteChatSession`）时，系统不仅清理本地磁盘文件，还自动遍历提取会话生命周期内全部关联的 `interactionId` 集合，在后台多协程并发调用注销接口彻底销毁云端资源，杜绝云端幽灵节点残留；
- **乐观链式交互与 404/过期无缝自愈续接 (Context Re-anchoring)**：
  - Interactions API 云端数据保留周期根据 Google 账号等级自动浮动（Free 1天，Paid 7~55天），且 API 协议中并不提供 TTL 或过期时间戳；
  - 系统采用零时延乐观推进策略（杜绝前置 GET 探测增加网络往返延迟），在多轮对话首轮与重新生成时，若捕获到云端 Interaction 出现 404、`expired`、`not_found`、或 `interaction does not exist` 时，底层自动将本地保存的历史消息序列化转换为标准化的 `<conversation_history>` 容器无缝拼装至当前提示词头部，自动重置 `previousInteractionId = null` 并发起无缝重试；
  - 自愈重试成功后，系统自动提取生成的新 `interactionId` 重新锚定为会话主键并持久化落盘，确保用户在经历长期会话间隔后完全无感知、零报错、零断流。

### 7. 异步生图任务中枢与结果就地内联呈现机制
- **秒级异步提交与任务句柄**：
  - `generate_image` 改造为秒级异步提交机制，入参校验通过后立即返回唯一的 `jobId` 与后台执行状态，彻底消除大模型与网络客户端的长耗时等待阻塞；
- **状态轮询工具与四阶生命周期**：
  - 配套提供 `query_image_job(jobId)` 专用轮询工具，支持实时查询任务的四阶生命周期状态（`SUBMITTED` 提交中 -> `RUNNING` 生成中 -> `SUCCESS` 成功 / `FAILED` 失败）；
  - 任务执行中实时返回当前进度（%）与已耗时；任务完成时返回包含图片真实规格、Base64 数据及本地 Data URI 的完整产物；
- **工具卡片结果就地内联呈现与资产操作栏二元白名单**：
  - `ToolExecutionStatusCard` 工具卡片原生内联渲染 `record.imageUri`，生成图片直接在调用工具正下方即时显示；
  - **二元白名单精准管控**：仅限明确属于视觉资产生成类的工具（`generate_image`、`query_image_job`、`chat_refine_image`、`generate_block_asset`、`generate_all_assets`）产出的图片，才会在卡片下方挂载「存入素材库...」与「添加到当前页面」操作栏；
  - 属于系统观测、自审与排版测试的截图类工具（如 `screenshot_window`、`compose_page_screenshot`、`render_template_overlay` 等）产出的图片仅作为视觉对账展示，绝对严禁展示素材资产操作栏，彻底避免用户混淆与无意义的误操作。
- **会话规范存储与按需入库**：
  - 生成图片默认完整保留在会话日志中，是否落盘归档至素材库由用户在操作栏手动触发或由后续 AI 调用指定，严格遵循数据隔离原则。
- **UI Studio 生图执行引擎合一 (Unified Image-Gen Engine)**：
  - UI Studio Agent 中无论用户选择普通对话模型（经 Function Calling 回调 `generate_image`）还是生图专属模型（生图轮由代码构造合成 `generate_image` 调用，`modelName` 透传用户所选模型），**生图执行一律统一经 `GenerateImageTool → ImageJobManager → AIGenerationService.generateImages` 同一管道**，完整享有批次重试、本地透明抠图与素材库归档能力；界面交互（模型菜单自由选择、消息卡片出图呈现）保持现状不变；
  - 生图专属模型轮次不再经 `GeminiChatEngine` chat 通道直连出图，由 `AiAgentDelegate.executeImageGenTurnViaUnifiedTool` 统一编排：生成图像自动落盘至项目 `chat_attachments/` 目录后以图片卡片呈现，会话持久化保持轻量；
  - `generate_image` 工具新增三个可选参数（对 MCP 通道完全向后兼容，缺省行为不变）：`targetWidth` / `targetHeight`（精确像素尺寸，成对提供且宽高比在 0.05~20 内时优先于 aspectRatio 枚举档位，支撑“选中图元同尺寸换风格重生”场景）、`waitSeconds`（同步等待秒数，默认 0 保持秒级异步提交语义，>0 时阻塞至任务终态并返回 `results` 完整产物数组）；
  - `ImageJobManager` 新增 `awaitJobCompleted(jobId, timeoutSeconds, pollIntervalMs)` 挂起轮询辅助（默认 120s，物理夹具 5~300s），供同步语义与编排方复用；`generate_image` 工具超时上限同步提升至 310s 以覆盖同步等待窗口。

## 四、 行业业务规则与安全红线

1. **【密钥安全性红线】**：API Keys（特别是 Gemini 与相关后端凭据）绝对禁止在日志、控制台或对外报文中明文输出，必须进行脱敏显示；
2. **【交互轮次守恒铁律】**：在官方 Interactions 协议下，系统指令属于 Interaction-scoped，每轮交互必须完整重发 `system_instruction`，杜绝多轮交互角色丢失；
3. **【多模态生图载荷自适应提取规范】**：在解析 Interactions API 与 GenerateContent 协议返回的流式多模态生图产物时，解析器必须同时兼容传统 `inlineData` / `inline_data` 结构以及 Interactions API 原生流式 `delta: { mime_type, data }` 直接返回图像的报文，杜绝在模型仅返回图片 Base64 产物且无独立文本时发生空响应误判；
4. **【排版方案卡片与流式文案渲染门禁规范】**：
   - 排版布局方案卡片必须以提取到真实且非空的 `elements` 数组图元为准入前提，严禁仅凭报文中包含 `edit_view_layout` 关键字粗暴拦截，彻底杜绝普通对话中因提及工具名而导致 AI 真实回复被覆盖并产生假排版方案数据兜底的缺陷；
   - 气泡组件必须支持直接接入 `streamingText` 流式文本，保证模型在逐字生成阶段即时渲染打字流效果，并在多轮工具执行后等待最终文本时提供平滑微光加载提示；
5. **【非阻塞防假死】**：AI 生成与多模态推理必须运行在后台异步协程调度器，严禁阻塞 UI 渲染主线程；
6. **【AI 声明式万能排版与复合流水线规范】**：AI 针对界面的排版与图元微调，强制统一调用工业级万能排版工具（`edit_view_layout`）。工具采用 `operations` 数组流水线机制，统一使用 `elements` 描述图元载荷，支持三大核心模式组合调用：① `REPLACE_PAGE`（整页重构/新建，自适应更新视口宽高）；② `REPLACE_CONTAINER`（指定 `targetId` 目标容器，仅局部替换其子图元，杜绝误杀整页）；③ `PATCH`（声明式精确补丁，按 `op: UPDATE/ADD/REMOVE` 执行局部增删改）；修改后系统自动针对变动页面执行原子落盘与多层引用组件树的跨页面镜像同步，且排版工具执行后系统自动构造 `ToolCallRecord` 向大模型反哺 FunctionResponse，彻底解除工具循环硬中断；
7. **【异步生图轮询与下游依赖阻断红线】**：`generate_image` 属于秒级提交任务，返回 `jobId` 并不代表生图完成；AI 在调用 `generate_image` 后必须循环调用 `query_image_job(jobId)` 轮询其完成状态；在 `query_image_job` 确凿确认产物就绪（返回 `SUCCESS`）之前，**绝对严禁**执行任何依赖该生图结果的下游联动任务（如界面排版 `edit_view_layout`、节点点击 `click_ui_node`、截图或下发关联操作），确保上下游依赖链条严格守恒闭环。
8. **【界面修改后原子持久化与保存闭环铁律】**：系统为 AI 核心工具白名单常驻配备 `save_project` 工具；凡是通过 `edit_view_layout` 或其他手段对图元、样式、尺寸进行修改后，系统在底层自动执行全工程（所有变动页面 + `template.json` + `workspace_layout.json`）原子持久化刷盘并清空脏状态（`isDirty = false`），同时约束 AI 必须主动调度 `save_project` 工具闭环确认落盘，杜绝仅在内存留存导致软件关闭时修改丢失。
9. **【AI 会话异常自动重试与零污染错误自愈铁律】**：
   - 系统为网络瞬态异常（包括 `UnresolvedAddressException`、网络连接超时、SocketTimeout、503 服务过载、429 配额限制等）提供全链路自动退避重试能力；重试次数由设置面板“AI 会话异常自动重试次数”动态管控（出厂默认 10 次，不设人为上限，支持任意非负整数）；
   - 当遇到网络/服务异常时，严禁向客户端弹出阻断式或烦扰型 Toast 红色浮层；异常信息必须且仅能在会话气泡内通过专业的 `ChatErrorActionCard` 高亮展示，并提供结构化排查指引与「重新生成」快捷操作；
   - 异常发生时，系统绝对禁止向 `VisualChatMessage.prompt` 中硬编码注入机械错误字符串，确保本地通信日志与大模型多轮历史上下文绝对纯净（零污染）；当用户点击重试或网络恢复重新请求成功后，系统自动将 `isError` 置为 `false` 并清空 `errorMessage`，错误卡片在毫秒级内自动消除自愈。

10. **【图片落盘素材库受控授权与人机确认铁律】**：
    - AI 持有临时生图或 Base64 图片数据时，**严禁擅自静默落盘至项目素材库**；
    - 在调用 `save_image_to_asset_library` 工具之前，**必须首先调用 `ask_user_question` 向用户汇报拟落盘的意图**：包括 AI 自动命名的语义化英文文件名（如 `bg_beach_soccer`）、拟归入的素材库子目录（如 `backgrounds`）、以及图片格式（JPG / 透明 PNG 去背）；
    - 仅当用户明确点击同意或授权放行后，方可调用 `save_image_to_asset_library` 完成物理写入与素材账本登记。
11. **【界面图元装配全景方案先行与独立二次确认铁律】**：
    - 素材入库仅代表资产就绪，**绝对禁止未经确认直接调用 `edit_view_layout` 装配到界面**；
    - 装配前必须基于当前图元树分析，向用户输出完整的【5维全景装配方案卡片】：① 装配模式（替换现有容器还是新建图元）；② 归属父容器（目标 `targetId`）；③ Z-Order 渲染层深；④ 逻辑坐标与目标宽高；⑤ 组件类型与语义；
    - 获得用户二次明确同意后，方可调用 `edit_view_layout` 执行装配，并在底层由素材库哈希强校验机制保障绑定的 `assetHash` 真实合法。
12. **【页面新增与宏观重构方案先行确认铁律】**：
    - 严禁在接收到模糊或宏观重构指令时（如“帮我重做主页”、“添加设置界面”）直接全量调用 `edit_view_layout(mode: REPLACE_PAGE)` 覆写当前界面；
    - 必须遵循“探测 ─► 方案 ─► 确认 ─► 执行”四部曲：① 先调用 `get_template` 探测当前工程页面、分辨率与素材现状；② 向用户汇报包含页面纯英文标识符 (`viewName`)、画布分辨率与核心模块清单的大纲方案；③ 通过 `ask_user_question` 单选卡片获取确认授权；④ 获批后方允许调用 `edit_view_layout`，执行后调用 `save_project` 持久化。
13. **【组件新建、删除与跨容器迁移 5 维结构方案确认铁律】**：
    - 凡涉及当前页面的图元新增 (`ADD`)、删除 (`REMOVE`)、或跨父容器迁移等结构级变更，严禁擅自直接分发工具执行；
    - 必须先审查当前页面图元树，向用户提呈包含【装配模式、归属父容器、Z-Order前后遮挡关系、坐标尺寸、组件语义】的结构方案卡片，经 `ask_user_question` 确认后方可调用 `edit_view_layout`。
14. **【微观精准属性指令低摩擦直通与撤销兜底铁律】**：
    - 仅当用户明确指示具体数值或文本微调参数时（如“把标题文案改成‘游戏大厅’”、“把这个按钮向右移动 20px”、“透明度调为 0.5”），AI 豁免弹窗确认，允许直接调用 `edit_view_layout(mode: PATCH)` 执行并即时在对话中清晰反馈修改结果，系统内置撤销栈保障高沉浸感与低摩擦操作流。
15. **【三级分流确认安全门禁双重防御体系】**：
    - 系统确立“规范层思维引导 + 工具层防呆拦截”双重防御机制：规范层通过出厂 System Prompt 严格塑造智能体行为认知，工具层通过 Schema 红线约束与 `edit_view_layout` 容器边界防覆盖检查，坚决守住用户数据安全底线。
16. **【Interactions 节点生命周期一致性与自愈守恒铁律】**：
    - 客户端本地会话变更（消息删除撤销、会话清空、全量删除）必须 100% 触发后台云端对应 `interactionId` 的异步物理注销（`DELETE /v1beta/interactions/{id}`），杜绝云端残留孤儿会话节点；
    - 面对云端数据淘汰机制（Free 1天 / Paid 7~55天），客户端绝对禁止向用户弹出粗暴的 404 错误弹窗；底层必须统一拦截 404/expired 错误并触发“本地历史打包重锚定（Context Re-anchoring）”自愈流水线，以完全透明的方式完成多轮会话自动续接。
17. **【用户决策问询人机工程学与解耦闭环规范 (AskUser Ergonomics & Decoupled Architecture)】**：
    - **同步阻塞、无限挂起等待与零僵尸弹窗安全门禁**：交互类工具（`ask_user_question`、`ask_user_choice`、`ask_user_confirmation`）在入参未显式传入 `async` 时，底层执行逻辑**强制默认为同步阻塞模式（`isAsync = false`）且无限期挂起等待用户真实操作（`timeoutMs = Long.MAX_VALUE`）**，绝不因用户离开或阅读方案超时（如 240 秒）而擅自超时跳过用户决策；当后台等待协程因用户点击停止按钮取消或异常退出时，`McpInteractionBridge` 自动向 `McpInteractionHost` 广播 `McpInteractionRequest.Dismiss` 事件毫秒级同步关闭前台弹窗，彻底杜绝残留无法交互的“僵尸弹窗”；问询弹窗（`AskUserQuestionDialog`）彻底移除右上角 Close 按钮与底部取消按钮，禁用 ESC 键与外部遮罩点击退出（`dismissOnBackPress = false, dismissOnClickOutside = false`），强制用户通过明确选项做出单向决断，彻底根绝意外关闭导致后台协程死锁；
    - **1200dp 宽屏与 94% 视口极限弹性高度**：问询弹窗彻底摆脱人工写死的高度限制，基于 Compose 原生 `Dialog + BoxWithConstraints + Surface` 打造全屏宽屏弹性外壳，宽度自适应扩展至 **1200dp**（自适应视口 96% 弹性拉伸），最大高度开放至当前视口高度的 **94%**（几乎贴边拉满屏幕垂直可用空间）；
    - **纵向自适应三段式解耦**：正文方案描述区与选项卡片区彻底分离：
      ① 正文大纲区外层包裹 `SelectionContainer`，原生支持鼠标自由划词高亮与 `Ctrl+C` 复制大纲内容；正文彻底废除硬编码高度上限，纯粹采用 `Modifier.weight(1f, fill = false)` 自适应弹性舒展，短文案紧凑收敛零空白，面对 25~30 行复杂大纲时自动拉伸撑满屏幕剩余的全部纵向空间，直至达到 94% 视口极限后才由专属垂直滚动条 `VerticalScrollbarAdapter` 平滑滚动，彻底杜绝小窗口局促感；
      ② 选项卡片区（包含推荐方案置顶徽章卡片、普通方案卡片、原位变形自定义输入卡片、常驻内置终止任务卡片）完全脱离滚动容器，永远完整平铺可见，绝不滚出视口；
    - **自定义答案原位内联变形为输入框 (In-Place Transforming Card)**：
      自定义答案选项摒弃传统的“下挂额外输入框”冗余结构，采用内联无感变形卡片 `CustomAnswerOptionCard`：
      - 未激活态：保持标准选项卡片外观（单选框 + 标题“自定义答案” + 副标题说明）；
      - 激活态：点击后直接在该卡片内部**原位切换为无边框透明内联输入框**，原本的文案直接转化为占位提示词（Placeholder），点击瞬间自动获取光标焦点，用户可直接敲击键盘输入补充意见，右下角「确认选择」按钮实时高亮点亮；零多余外挂控件，零视觉层级割裂；
    - **常驻安全退出通道**：选项区末尾固定常驻「结束任务（放弃修改并终止对话）」退出通道；用户选中提交后，工具直接向大模型反哺明确的拒绝意图（`reason: "user_terminated"`），并物理中断多轮工具循环，彻底消除误操作与不可控执行风险。
18. **【工具声明单一事实源与零去重安全红线 (Single-Source Tool Declaration & Zero-Deduplication Redline)】**：
    - 向大模型（如 Google Gemini）下发 Function Declarations 工具清单时，所有工具的 JSON Schema 定义**必须且仅能以中立工具类（如 `EditViewLayoutTool` 实现 `ToolDefinition`）为唯一事实源**；
    - 严禁在业务管理者（如 `UiStudioSkillManager`）或请求组装管道中手动重复硬编码同一工具的 Schema 声明；
    - 传输管道中**绝对禁止使用 `distinctBy` 等静默去重过滤器**进行掩盖兜底；任何重复注册或契约冲突必须通过单一事实源治理直接消除病因，确保语法、参数与注册流程的 100% 透明严谨，杜绝因隐藏静默缺陷而破坏底层系统的错误暴露与自检能力。
19. **【页面数据异常诊断与修复指引工具规范 (diagnose_view_data)】**：
    - 系统为外部 MCP 客户端与内置 AI 架构师常驻配备专用数据完整性诊断工具（`diagnose_view_data`），纳入 `CORE_TOOL_NAMES` 核心直通集合；
    - 工具复用纯静态诊断分析器 `StudioDataDiagnostics`，提供对当前工程或指定视图（`viewName`/`viewId`）的结构化体检能力，精准识别两类数据异常：① `REFERENCE_WITH_CHILDREN`（图元引用了独立页面却仍包含冗余历史子图元）；② `TARGET_PAGE_NOT_FOUND`（引用的目标页面不存在）；
    - 工具返回结构化异常清单及针对每一项问题的 `repairGuidance` 具体修复指引，引导大模型使用 `edit_view_layout` 正确执行排版与修复，形成“诊断 ─► 建议 ─► 排版修复 ─► 保存”的完整治理闭环。
