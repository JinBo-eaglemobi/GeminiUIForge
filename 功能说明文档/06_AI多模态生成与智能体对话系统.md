## 一、 模块核心定位

AI 体系是 Gemini UI Forge 的智能大脑与核心生产力引擎。系统覆盖了从**微观图元 AI 生图替换**、**全图多模态模板反向生成**，到**项目级 AI 架构师对话协同**（图元布局理解、代码建议、资产检索）。系统底层遵循企业级四层协议解耦标准，在保证极致大模型隐式缓存命中率（降低延迟与 Token 开销）的同时，提供完整的离线报文审计与图片缓存自愈机制。

## 二、 核心功能清单

### 1. 标准双语提示词编辑器 (BilingualPromptEditor)
- **中英双语无缝切换与智能参考**：
  - 单行分段按钮（SegmentedButton）结构，防换行折叠；
  - 支持分别独立编辑中文提示词（`userPromptZh`）与英文专业提示词（`userPromptEn`）；
  - 跨语言智能占位：编辑中文时自动浮现英文参考文本，反之亦然；
- **胶囊式 AI 提示词智能优化**：
  - 内置 34dp 优化按键，一键调取大模型对原始粗糙描述进行艺术风格、光影材质与细节扩充；
  - 自带平滑加载动画与多重点击防抖拦截；
- **变动感知与显式确认同步**：
  - 具备脏数据感知机制，用户修改或 AI 优化后动态高亮“确认修改”；
  - 只有显式点击确认后方才持久化回图元模型，杜绝非预期篡改。

### 2. 批量资产生成中心 (BatchAssetGenDialog)
- **纯容器智能过滤**：
  - 自动遍历当前工程图元树，100% 自动剔除所有纯容器（`isPureContainer = true`）与空白背景；
- **队列调度与进度回显**：
  - 支持全选、反选、单图元勾选；
  - 顺序/并发分发生图请求，实时展示生成缩略图与单项耗时，生成完毕后支持一键全量替换至工作区。

### 3. 项目级 AI 架构师通用对话体系 (CommonChatStudioDialog)
- **业务解耦与通用插槽模型**：
  - 全项目对话体系收拢于纯净通用组件库（`component/chat`），严禁业务专有逻辑污染；
  - 开放四重插槽扩展定制：顶部操作栏动作（`topBarActions`）、单消息气泡动作（`messageActions`）、输入框前置工具（`inputLeadingActions`）与后置发送扩展（`inputTrailingActions`）；
- **@提及图元与切片联想系统 (Mention System)**：
  - 用户在输入框键入 `@` 时，实时呼出历史引用、切片素材、素材库文件夹、视图界面与图层图元联想悬浮卡片（`MentionItemRow`）；
  - **素材库文件夹（含深度子文件夹）定向注入**：
    - 支持实时探测素材库中的全部自定义文件夹，展示包含切片总数（含全部子孙目录统计）及完整层级相对路径；
    - 选中文件夹后，挂载为 `📁 文件夹名 (共 N 项)` 专属药丸，与“全部素材库清单”同等待遇；
    - 发送时自动深度递归提取该文件夹及其所有深度子目录内的全部素材，按 `AssetManifestHelper` 转换为紧凑清单 `<asset_folder_manifest>`，**严格遵循资产唯一 Hash 驱动契约**（格式为 `- [hash: xxx] 文件名 [宽x高] | 角色: xxx`），彻底剔除无意义的本地物理文件路径；大模型在调用排版工具（`apply_view_layout`）装配图元时，一律使用该 `assetHash` 唯一主键精准绑定材质；
    - 会话气泡中的药丸与输入框胶囊均支持点击弹出 Markdown 沉浸式切片清单表格预览，表格核心字段由切片名、资产唯一 Hash、尺寸及语义角色构成，零冗余路径字段；
  - 采用跨平台纯 Kotlin 集合与模糊拼音/字母匹配，高亮命中字符；
  - 点击选中的图元/切片作为上下文结构化卡片挂载在输入框，发送时自动携带该图元的精确几何参数与切片信息；
- **剪贴板位图快捷捕获**：
  - 输入框原生监听系统级快捷键 `Ctrl+V` / `Cmd+V`，直接读取系统剪贴板中的截图或位图，秒级挂载为对话附件；
- **大模型动态探测与思考等级**：
  - 动态从 `GeminiModel.entries` / `StudioModelResolver` 读取最新可用模型矩阵，绝不硬编码老旧版本；
  - 集成思考等级调节器，按需调节思考深度（Low、Medium、High）。

### 4. 四层协议载荷解耦架构规范 (Four-Tier Payload Decoupling)
系统与大语言模型通信严格遵循工业级四层物理载荷解耦：
1. **纯净静态系统指令 (Pure Static System Instruction)**：
   - `systemInstruction` 专职且仅承载智能体元身份定位与安全准则；
   - **严禁拼接动态图元树或临时文档**，确保系统指令全局静态一致，100% 触发大模型官方隐式上下文缓存（Implicit Caching），极速降低延迟；
2. **外部资料的数据属性隔离**：
   - 用户拖入的参考文档、需求表仅作为用户消息内的 `<reference_documents>` 隔离数据块传输，并附带防注入隔离声明；
3. **动态环境轮次注入 (Workspace Observation)**：
   - 当前画布视口分辨率与素材状态作为运行时环境观察，绑定于提问时刻的当前轮次，杜绝跨轮次幽灵状态污染；
4. **原生 Function Calling 工具调用**：
   - 技能与操作通过标准工具定义下发，拒绝长篇大论的手册塞入人设；
   - 默认下发精炼核心工具（`CORE_TOOL_NAMES`），并专属配备批量素材获取工具 **`get_assets`**，支持大模型在规划布局前通过 `assetHashes: Array<String>` 批量提取素材真实规格、语义角色与可选的 Base64 图像，彻底打通 Hash 主键与排版装配的闭环链路。

### 5. 通信报文审计与本地缓存自愈机制
- **标准化磁盘分级存储**：
  - 生成图片落盘：`~/.geminiuiforge/templates/{projectName}/assets/{blockId}/`；
  - 原始通信完整报文：`~/.geminiuiforge/sessions/{safeScope}/{sessionId}/traffic/`；
- **报文检视与巨型载荷脱敏折叠**：
  - 通信报文档案卡片针对请求/响应报文中数万至百万字符的巨型 Base64 图片载荷与 Gemini 3 系列思维链签名（`signature` / `thought_signature`）自动执行 UI 级脱敏折叠，彻底根除 Compose 文本组件内存溢出与主线程掉帧；
  - **双模态操作与二元差异化查看器**：卡片 Header 动态识别并展示“含图像”（`Image`）与“含签名”（`Psychology`）双徽章，在卡片操作栏与报文文本底部提供直达按钮；图片载荷唤起带格式魔数校验（PNG/JPEG/WEBP/GIF）的高清 Base64 图像预览器，签名载荷唤起思维签名查看器并支持一键复制，实现图像与数字签名的二元完全解耦；
- **自动再次缓存与自愈恢复**：
  - 当本地磁盘的生成图片被意外删除或转移时，用户在历史会话中点击「应用」，系统自动回溯读取对应轮次的 `RESP.json` 完整通信报文，重新解码提取 Base64 图片数据并无感重新写回磁盘，实现绝对的高可用闭环。

## 四、 行业业务规则与安全红线

1. **【密钥安全性红线】**：API Keys（特别是 Gemini 与相关后端凭据）绝对禁止在日志、控制台或对外报文中明文输出，必须进行脱敏显示；
2. **【交互轮次守恒铁律】**：在官方 Interactions 协议下，系统指令属于 Interaction-scoped，每轮交互必须完整重发 `system_instruction`，杜绝多轮交互角色丢失；
3. **【多模态生图载荷自适应提取规范】**：在解析 Interactions API 与 GenerateContent 协议返回的流式多模态生图产物时，解析器必须同时兼容传统 `inlineData` / `inline_data` 结构以及 Interactions API 原生流式 `delta: { mime_type, data }` 直接返回图像的报文，杜绝在模型仅返回图片 Base64 产物且无独立文本时发生空响应误判；
4. **【排版方案卡片与流式文案渲染门禁规范】**：
   - 排版布局方案卡片必须以提取到真实且非空的 `blocks` 数组图元为准入前提，严禁仅凭报文中包含 `apply_view_layout` 关键字粗暴拦截，彻底杜绝普通对话中因提及工具名而导致 AI 真实回复被覆盖并产生假排版方案数据兜底的缺陷；
   - 气泡组件必须支持直接接入 `streamingText` 流式文本，保证模型在逐字生成阶段即时渲染打字流效果，并在多轮工具执行后等待最终文本时提供平滑微光加载提示；
5. **【非阻塞防假死】**：AI 生成与多模态推理必须运行在后台异步协程调度器，严禁阻塞 UI 渲染主线程。
