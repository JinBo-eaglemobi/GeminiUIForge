# 参考图反向生成 UI 模块工程全流程执行规范 (IMAGE_TO_MODULE SOP)

> 📌 **适用场景与触发词 (Trigger & Scope)**：
> 当接收到以下指令时必须强制全量执行本规范：
> - “执行将 `<图片路径>` 生成模块 / 模板”
> - “根据参考图生成 UI 模块 / 模板工程”
> - “从设计图反向提取图元并校准”
> 
> **防混淆与任务定性铁律 (Disambiguation Guard)**：
> 1. **严禁与“AI 生图/资产重绘”混淆**：本任务是**“将设计图逆向解析为 UI 页面骨架、层级组件树、坐标与双语提示词”**，**绝对不是**向模型索要新图片或调用 `generate_block_asset` / `generate_all_assets` 进行资产贴图生图！
> 2. **未生图阶段的几何边框包裹吻合度为唯一判定铁律 (Bounding Box Enclosure Rule)**：
>    在初次从参考图反向生成模板阶段，各图元尚未绑定任何 AI 生成图片资产（无贴图），此时**绝对严禁**依据 SSIM、CAS 或 Diff 像素重合度算法做误判！此时唯一权威的核验准绳是：**“图元青色矩形边框（Bounding Box）与参考底图中对应真实预定内容（如按钮图标、文字、金币、圆盘控制器、转轴网格等）的物理包裹吻合度”**：
>    - **零切边红线**：图元按钮、图标主体、徽标或文字严禁被外框裁切削边；
>    - **零多余留白红线**：外框严禁过度虚胖外扩，留出大量无关背景空隙；
>    - **严密居中包裹**：内容必须紧凑居中在矩形边框内；一旦发现偏离，**必须立即调用 `gemini-ui-forge_update_block` 精准纠偏**，严禁草率放行！
> 3. **全量业务图元 100% 逐一微观核验门禁（严禁抽检走过场）**：
>    首态算法自愈只是机器初筛，大模型初始坐标往往仅 60%~80% 粗糙度。AI **必须 100% 遍历模板中所有非纯容器业务图元**（严禁只挑 2~3 个模块抽检），逐个生成 1:1 局部特写并亲眼核验边框贴合度，最终交付报告必须输出全量图元核验表格。
> 4. **严禁全屏截图交差**：校对过程与交付凭证，**100% 严禁截取全屏大图**，必须且仅能截取**目标模块外扩 32~48px 的局部 1:1 高清特写**。

## 模式分流准则：跟随模式与快捷无感模式 (Dual-Mode Architecture)

在执行具体构建前，AI 必须通过 `gemini-ui-forge_get_ui_roadmap` 检查系统运行参数 `isUiFollowEnabled`：

| 运行模式 | `isUiFollowEnabled` 状态 | 核心交互原则 | 界面行为与用户保护 |
|---|---|---|---|
| **分支 A：跟随模式 (Foreground Interactive)** | `true` | **完全拟人前台交互**，禁止越级调用非人工途径 | 前台全流程视觉可见；主界面手势锁定（放行底部 30dp 状态栏）；大厅卡片显示生成中遮罩并禁止点击 |
| **分支 B：快捷无感模式 (Headless Offline)** | `false` | **全程后台静默执行**，零干扰前台当前界面 | 程序保持在当前任何界面，零界面跳转；大厅卡片显示生成中遮罩并禁止点击；基于 Skia 离屏渲染与本地物理落盘核验 |

## 阶段零：前置环境准备与模式判定 (Preflight & Routing)

1. **资源存在性检查**：
   - 物理探测用户传入的图片路径是否存在，严禁基于虚构路径请求接口。
2. **工程命名决议**：
   - 若用户未显式指定工程名，根据图片主文件名推导安全标识（如 `reference_0.png` $\rightarrow$ `reference_0`，仅小写字母、数字与下划线）。
3. **路线图感知与模式路由**：
   - 调用 `gemini-ui-forge_get_ui_roadmap` 获取 `isUiFollowEnabled` 与 `currentScreen`；
   - 根据 `isUiFollowEnabled` 自动分流：
     - 若为 `true` $\rightarrow$ 进入 **【分支 A：跟随模式流程】**；
     - 若为 `false` $\rightarrow$ 进入 **【分支 B：快捷无感离线流程】**。

## 分支 A：跟随模式全流程 (Foreground Interactive Follow Workflow)

> 适用条件：`isUiFollowEnabled == true`。本模式下要求完全模拟人工在 Compose 界面上的正常交互步骤，严禁直接调用无头跳步接口。执行全程主界面手势锁定，仅最底部 30dp 状态栏可供用户查看日志。

### A1. 大厅归位与手势锁定
1. **排空工作区脏数据**：
   - 若当前在工作区 (`PROJECT_WORKSPACE`) 且 `isDirty == true`，模拟点击返回图标，在未保存弹窗中点击“不保存退出”；
   - 确保当前界面回到模板列表大厅 (`TEMPLATE_LIST` / `HOME`)；
2. **激活防误触保护**：
   - 系统检测到跟随模式执行时会自动锁定主内容区点击手势，用户乱点会弹出轻量 Toast 提示，底部 30dp 状态栏保持可用。

### A2. 点击“生成模板”按钮
1. 通过 `gemini-ui-forge_get_semantic_tree(query = "menu_generate_template")` 定位顶部导航栏的“生成模板”按钮；
2. 调用 `gemini-ui-forge_click_ui_node` 点击按钮，导航进入 `TEMPLATE_GENERATOR` 界面。

### A3. 输入参考图信息并触发生成
1. 在模板生成界面中，通过语义树定位输入框：
   - 参考图路径输入框：填入参考图片绝对路径；
   - 模板工程名输入框：填入解析出的 `projectName`；
2. 定位并点击“开始分析生成”按钮；
3. 大厅卡片与系统状态自动标记该工程为“AI 逆向生成中...”，在此期间禁止在大厅点击进入该卡片。

### A4. 等待完成与自动切入工作区
1. 等待大模型视觉分析、初次吸附纠偏与模板落盘；
2. 生成完成后，桌面端应用程序会自动平滑导航切入 `PROJECT_WORKSPACE`，并加载该模板。

### A5. 首次首态自愈与全景宏观视觉对账 【通用核心红线门禁】
1. **算法基础自愈**：
   - 调用 `gemini-ui-forge_trigger_initial_verification`；
   - 自动执行背景全屏归一化 `[0, 0, W, H]`、复合容器 `isPureContainer` 标记与微观边缘吸附；
2. **【强制前置门禁】离屏渲染全景标注图并执行全景宏观视觉三要素对账**：
   - **严禁直接跳入局部切片！** 局部切片存在“只见树木不见森林”的致命盲区（漏掉的模块永远看不到，飞脱错位的模块局部也看不出），**必须优先在全景宏观视角完成原图实体与线框的 1:1 对账**；
   - 调用 `gemini-ui-forge_render_template_overlay(stage = "initial")` 渲染首态全景标注图；
   - **通用视觉三大公理对账（与游戏类型 100% 解耦）**：
     - **① 漏检审计（缺少模块）**：从上至下扫描全景原图，任何具有独立视觉轮廓、色彩边界或交互特征的物理实体（如独立按钮、状态文本、进度条、徽标、卡槽等），若标注图中对应区域完全空白无框，**必须立即调用 `gemini-ui-forge_add_block` 补齐**；
     - **② 边界与粒度审计（错误模块）**：检查线框是否完整包裹实体的最外层物理轮廓（金属外壳框架、立体底座、发光轮廓、端头耳翼）；排查是否存在位置飞脱，排查是否存在“单个大框将多个独立按键粗暴打包在一块”；若有截断、飞脱或粗暴混装，**必须立即调用 `gemini-ui-forge_update_block` 修正绝对坐标或拆解添加子模块**；
     - **③ 幻觉审计（多余虚框）**：排查是否存在画在纯背景渐变、空白空地上的虚线框；若无对应实体，**必须立即调用 `gemini-ui-forge_delete_block` 剔除**；
   - **全景对账闭环断言**：重新调用 `gemini-ui-forge_render_template_overlay(stage = "latest")`，亲眼确认全景实体与线框达到 100% 宏观一一对应吻合后，方可进入 A6 逐图元微观核验。

### A6. 逐图元独立隔离、对齐核验与局部高清审查 【微观精修门禁】
读取 `get_template` 中的全量图元树，过滤掉 `isPureContainer == true` 的容器，提取出全部**非纯容器业务图元清单**。AI 必须对清单中的**每一个业务图元执行 100% 全量审校**，严禁抽检跳步：
1. **单图元隔离、微观对齐与局部切片截屏**：
   - 调用专用工具：`gemini-ui-forge_inspect_block_with_reference`；
   - 关键参数：
     - `projectName`: `<工程名>`
     - `blockId`: 当前模块 ID
     - `calibrate`: `false`（初次生成未贴图阶段不触发贴图校对）
     - `cropRegionOnly`: `true`（**核心红线**：仅截取目标图元周围局部外扩 32px 区域，严禁全屏大图）
     - `padding`: `32`
     - `overlayOpacity`: `0.5`
     - `evaluateOverlap`: `false`（无贴图阶段由工具自动切换为 MODE_GEOMETRIC_BOUNDS 几何边框模式）
2. **几何边框包裹吻合度判定（未生图阶段唯一准绳）**：
   - AI 亲眼审查回传的局部 1:1 高清特写截图（青色矩形边框叠在参考图上）：
     - **零切边检查**：目标按键、图标边缘、文字标牌、徽标是否被青色外框截断？若切边，必须外扩对应方向坐标；
     - **零过度留白检查**：青色外框是否过大，多框入了大量不属于该组件的背景？若留白过大，必须收缩对应坐标；
     - **居中严密性检查**：组件是否在边框中紧凑居中？
     - **底座完整性检查**：排查外包矩形是否仅框住了内部反光板或局部文本，而将外部物理底座截断遗漏在框外；若被截断，外包矩形必须外扩至最外层实体轮廓；
     - **正圆外切度检查**：视觉正圆组件的宽高比是否恒等于 1:1，四边是否与最外层发光圆环严密切合；
     - **实体底座属性检查**：凡具备独立材质纹理的承载底座，严禁标记为纯容器；
   - 若发现任何切边或偏离，**必须立即调用 `gemini-ui-forge_update_block` 修改 bounds 与属性纠偏**，纠偏后可再次调用核验确认！
3. **真实落盘物理凭证提取**：
   - 每次调用审查工具后，必须从工具实际返回值中提取该截图在本地磁盘上的真实保存绝对物理路径，供后续交付报告使用，绝对严禁脱离实际返回值脑补任何假想路径或虚拟目录。

### A7. 保存与交付
1. 调用 `gemini-ui-forge_click_ui_node` 点击工作区顶部保存按钮（`btn_save`），将最新数据与切片绑定持久化写回磁盘；
2. 任务完成，系统自动解除手势锁定，输出标准化全量交付报告。

## 分支 B：快捷无感离线流程 (Headless Offline Quick Workflow)

> 适用条件：`isUiFollowEnabled == false`。本模式下要求**全程后台静默执行**，程序在什么界面就保持在什么界面，绝不干扰用户当前前台视口；依赖纯离线 Skia 渲染引擎与算法对齐库，并将局部 1:1 审校截图物理落盘本地。

### B1. 静默生成中状态标记
1. AI 获取目标工程名后，系统状态将该工程自动纳入 `generatingProjects`；
2. 用户在前端大厅中会看到该卡片展示“AI 逆向生成中...”优雅动效遮罩；若用户尝试点击进入，系统直接弹窗拦截并保护数据完整性；
3. **前台界面零跳转**：程序留在当前任何界面（不管是大厅、设置还是其他工程），AI 绝不触发任何破坏当前画面的导航事件。

### B2. 快捷调用后台生成接口与异步长轮询保活 【防超时核心】
1. **触发异步生成任务**：
   - 调用工具：`gemini-ui-forge_analyze_reference_generate_template`；
   - 关键参数：
     - `projectName`: `<工程名>`
     - `referenceImages`: `["<图片物理绝对路径>"]`
     - `autoCropReferenceImage`: `false`
     - `async`: `true`（**防超时铁律**：默认开启异步模式，10ms 内立即返回 `jobId`，彻底免疫客户端 60 秒硬超时）
2. **服务端长轮询监听完成**：
   - 提取返回的 `jobId`；
   - 调用 `gemini-ui-forge_get_job_status(jobId = jobId, waitSeconds = 25)` 进行自适应长轮询；
   - 服务端会在协程挂起自适应等待，若大模型提早生成完毕则瞬时返回；若返回状态仍为 `RUNNING`，则继续调用查询，直至 `status == "COMPLETED"`；
3. 确认模板物理落盘成功后，继续进入后续首态自愈流程。

### B3. 离线触发首态自愈与全景宏观视觉对账 【通用核心红线门禁】
1. **离线算法初治**：
   - 直接调用：`gemini-ui-forge_trigger_initial_verification`；
   - 底层工具自动接线 `bindParents()`、背景全屏归一化 `[0, 0, W, H]`、复合容器规范化与 `SmartEdgeSnapper` 吸附；
2. **【强制前置门禁】离屏渲染全景标注图并执行全景宏观视觉三要素对账**：
   - **严禁直接跳入局部切片！** 局部切片无法识别漏掉的模块与全景拓扑飞脱，**必须优先在全景宏观视角完成原图实体与线框的 1:1 对账**；
   - 调用 `gemini-ui-forge_render_template_overlay(stage = "initial")` 获取首态全景标注图；
   - **通用视觉三大公理对账（与游戏类型 100% 解耦）**：
     - **① 漏检审计（缺少模块）**：从上至下扫描全景原图，任何具有独立视觉轮廓、色彩边界或交互特征的物理实体（如独立按钮、状态文本、进度条、徽标、卡槽等），若标注图中对应区域完全空白无框，**必须立即调用 `gemini-ui-forge_add_block` 补齐**；
     - **② 边界与粒度审计（错误模块）**：检查线框是否完整包裹实体的最外层物理轮廓（金属外壳框架、立体底座、发光轮廓、端头耳翼）；排查是否存在位置飞脱，排查是否存在“单个大框将多个独立按键粗暴打包在一块”；若有截断、飞脱或粗暴混装，**必须立即调用 `gemini-ui-forge_update_block` 修正绝对坐标或拆解添加子模块**；
     - **③ 幻觉审计（多余虚框）**：排查是否存在画在纯背景渐变、空白空地上的虚线框；若无对应实体，**必须立即调用 `gemini-ui-forge_delete_block` 剔除**；
   - **全景对账闭环断言**：重新调用 `gemini-ui-forge_render_template_overlay(stage = "latest")`，亲眼确认全景实体与线框达到 100% 宏观一一对应吻合后，方可进入 B4 离线逐模块微观核验。

### B4. 逐图元离线 Skia 渲染、本地落盘与高清审查 【微观精修门禁】
遍历模板中所有非纯容器业务图元，提取全部业务图元清单，**100% 逐一执行后台无头离线校审（零遗漏、零抽检）**：
1. **调用离线单模块核验工具**：
   - 调用专用工具：`gemini-ui-forge_inspect_block_with_reference`；
   - 关键参数：
     - `projectName`: `<工程名>`
     - `blockId`: 当前模块 ID
     - `calibrate`: `false`
     - `cropRegionOnly`: `true`（**核心红线**：局部 1:1 切片，严禁全屏）
     - `padding`: `32`
     - `overlayOpacity`: `0.5`
     - `evaluateOverlap`: `false`
2. **Skia 离线渲染与物理文件落盘**：
   - 底层工具自动检测无贴图状态，以 `MODE_GEOMETRIC_BOUNDS` 模式在参考图上清晰绘制青色外框；
   - 渲染图片自动调用 `ImageCacheManager.saveCache` 写入本地物理缓存磁盘（路径返回于 `screenshotPath`），并回传 ImageContent；
3. **AI 离线多模态审校与纯数据纠偏（零切边、零过度留白）**：
   - AI 亲眼审查回传的局部特写切片；
   - 严厉排查是否存在**切边**（按键/图标被裁掉一块）或**过度留白**（边框比内容大很多）；
   - **底座完整性排查**：排查外包矩形是否仅框住了内部反光板或局部文本，而将外部物理底座截断遗漏在框外；若被截断，外包矩形必须外扩至最外层实体轮廓；
   - **正圆外切度排查**：视觉正圆组件的宽高比是否恒等于 1:1，四边是否与最外层发光圆环严密切合；
   - **实体底座属性排查**：凡具备独立材质纹理的承载底座，严禁标记为纯容器；
   - 若有任何不吻合，直接计算出准确的局部相对 bounds，调用 `gemini-ui-forge_update_block` 纠偏并落盘。
4. **真实落盘物理凭证提取**：
   - 必须从底层工具实际返回值（如 `screenshotPath` 字段）中直接捕获截图落盘的真实绝对物理路径，供最终矩阵表内嵌渲染，严禁脑补路径。

### B5. 数据收口与交付
1. 遍历核验与纠偏完毕后，所有修改已通过 `TemplateRepository` 完整落盘；
2. **执行首次交付前阻断级门禁断言**：确认全量非纯容器图元无底座截断、无正圆失真、无实体底座误标纯容器；
3. 触发一次 `gemini-ui-forge_trigger_initial_verification` 或更新状态自动将该工程从 `generatingProjects` 移除，解除大厅卡片点击锁定；
4. 向用户输出规范化的结构化交付报告。

## 交付报告统一格式规范（全量业务图元矩阵门禁）

无论通过分支 A 还是分支 B 完成，最终向用户汇报的内容必须结构化呈现，且**必须包含全量业务图元几何边框包裹度核验矩阵表**：
1. **运行模式注明**：明确标注本次执行走的是“跟随模式（前台拟人交互）”还是“快捷无感模式（后台静默离线）”；
2. **工程总体概览**：工程名、画布尺寸、总图元数（容器数 / 业务实体图元数）；
3. **图元层级架构清单**：列出识别出的主要区块（Header、Body、Footer、Reels 等）及核心子节点；
4. **【强制门禁】全量业务图元几何边框包裹度核验矩阵表**：
   - 必须 100% 覆盖模板中所有非纯容器业务图元，严禁抽检缩编；
   - 矩阵表字段：`图元 ID` | `业务显示名称` | `最终 Bounds` | `边框包裹核验结论（零切边/零留白/严密包裹）` | `【强制核验回显】局部核验图（真实磁盘绝对路径 + Markdown 内嵌渲染本体）`；
   - **【红线规则】回显真实性要求**：必须严格遵循《调用程序 MCP 截图审查的物理文件回显规范》，所有核验图必须显式输出真实的本地磁盘绝对物理路径，并通过 Markdown 图片语法直接在消息中渲染呈现图片本体画面，严禁仅输出纯文本说明、普通跳转链接或任何 404 空地址。

## 首次交付前阻断级检查单 (Pre-Delivery Blocker Checklist) 【红线铁律】

在模板逆向生成、自愈校准与首次交付前，必须 100% 逐项通过以下物理阻断断言；凡存在以下任一缺陷，强制判定为阻断级不合格（Blocker），必须先完成坐标与属性纠偏，绝对严禁解除大厅锁定或输出交付结论：
1. **实体漏框阻断**：原图存在明显独立的交互按键、状态栏、展示面板或核心图元实体，但在模板中完全缺失对应线框；
2. **位置飞脱与严重错位阻断**：线框与实体区域不重合或偏移超过其自身宽高的 30%，甚至跨区域画到了其它实体或空地上；
3. **粗暴打包未拆分阻断**：多个独立的交互按键或控制器被单个大框混装，未拆解定义出独立的子图元；
4. **底座截断阻断**：外包矩形仅框住内部反光板或文本而将外部金属/厚度底座拦腰截断；
5. **正圆失真阻断**：视觉正圆组件的宽高比偏离 1:1 或发光外环被切断；
6. **实体底座误标纯容器阻断**：带有独立视觉材质的物理底座被错误标记为不生图纯容器；
7. **层级文字重叠打架阻断**：子文本与容器标签发生重叠覆盖遮挡。
